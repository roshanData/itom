# Survey & Telemetry Investigation Handoff Report

## Executive Summary
This investigation conducted a complete data audit of the Microsoft Intune telemetry and IT Operations Management (ITOM) datasets, scripts, and dashboard interfaces within the workspace. The dataset contains **25,987 managed endpoint records** with a **83.08% fleet compliance rate** (21,589 compliant, 3,422 non-compliant, 935 configManager, 31 unknown, 10 inGracePeriod). Several critical implementation gaps and discrepancies were uncovered, including an unhandled case-sensitivity defect in manufacturer aggregation (`"LENOVO"` vs `"Lenovo"`), missing tab switching event listeners in `ops_analytics.js`, hardcoded storage percentage discrepancies in `ops_analytics.html`, and CSV export limited to 100 sample records.

### 1.3 Discrepancies and Implementation Flaws Found

#### Defect 1: LENOVO Manufacturer Case-Sensitivity Bug in `scripts/generate_dashboard_payload.py`
- **Code Quote** (`scripts/generate_dashboard_payload.py:28`):
  ```python
  mfg_clean = "Dell" if "Dell" in mfg else ("HP" if "HP" in mfg or "Hewlett" in mfg else ("Lenovo" if "Lenovo" in mfg else ("Apple" if "Apple" in mfg else "Other")))
  ```
- **Observed Behavior**: The manufacturer string in Intune data is `"LENOVO"` (all uppercase). Because `"Lenovo"` is case-sensitive, `"Lenovo" in "LENOVO"` evaluates to `False`. As a result, all 959 Lenovo devices were lumped into `"Other"` (giving `"Other": 1057` in `intune_summary.json`).
- **Resolution**: Use `"lenovo" in mfg.lower()`.

#### Defect 2: Hardcoded HTML Values Discrepancy in `ops_analytics.html`
- **Code Quote** (`ops_analytics.html:105-106`):
  ```html
  <div class="kpi-number" id="kpiStoragePct">41.8%</div>
  <div class="kpi-subtext">Average free disk space: ~58.2% across fleet</div>
  ```
- **Observed Behavior**: Before JavaScript loads, the HTML displays `41.8%` used / `58.2%` free. The true verified metric across the 25,987 dataset is `37.4%` used / `62.6%` free (`37.35%`).

#### Defect 3: Missing Tab Navigation Handlers in `ops_analytics.js`
- **Code Quote** (`ops_analytics.html:37-41`):
  ```html
  <nav class="dashboard-tabs">
    <button class="tab-btn active" data-tab="overview">Overview</button>
    <button class="tab-btn" data-tab="intune">Microsoft Intune (Live)</button>
    <button class="tab-btn" data-tab="solarwinds">SolarWinds (Pending)</button>
    <button class="tab-btn" data-tab="network">Network & CMDB</button>
    <button class="tab-btn" data-tab="dex">DEX Metrics</button>
  </nav>
  ```
- **Observed Behavior**: In `ops_analytics.js`, there is NO event listener or view-switching logic attached to `.tab-btn`. Clicking any tab has zero effect. Furthermore, `ops_analytics.html` lacks dedicated tab-view containers or filtering logic for SolarWinds, Network, and DEX sections.

#### Defect 4: Incomplete CSV Export (FR-006)
- **Code Quote** (`ops_analytics.js:12` and `ops_analytics.js:201`):
  ```javascript
  allDevices = dashboardData.sample_devices || [];
  // exportCSV maps allDevices
  ```
- **Observed Behavior**: `data/intune_summary.json` only contains 100 sample devices in `"sample_devices"`. When the user clicks "Export CSV" or "Export Complete Dataset (CSV)", only 100 records are exported instead of the full 25,987 devices.

## 2. Logic Chain

1. **Dataset Authenticity & Completeness**:
   - `data/intune_ops_analytics.json` contains 25,987 discrete JSON objects matching Microsoft Graph API schema.
   - All 25,987 objects contain valid `id`, `deviceName`, `operatingSystem`, `osVersion`, `complianceState`, `manufacturer`, and `lastSyncDateTime` fields.
   - Therefore, the dataset represents a genuine, high-fidelity ITOM enterprise telemetry snapshot.

2. **Metrics Consistency**:
   - Sum of OS counts ($25334 + 602 + 24 + 24 + 2 + 1 = 25987$) equals 100% of device array.
   - Sum of Compliance states ($21589 + 3422 + 935 + 31 + 10 = 25987$) equals 100% of device array.
   - Compliance rate calculation: $\frac{21589}{25987} \times 100 = 83.07615...\% \approx 83.08\%$.
   - Storage utilization calculation: $\frac{9761.55 - 6115.52}{9761.55} \times 100 = 37.3510...\% \approx 37.4\%$.

3. **Dashboard Consumption Mechanism**:
   - `ops_analytics.html` loads `ops_analytics.js`, which issues `fetch('data/intune_summary.json')`.
   - `ops_analytics.js` replaces the static HTML DOM text with `data.metrics`, and instantiates Chart.js graphs for `osChart`, `complianceChart`, and `mfgChart`.
   - However, because `intune_summary.json` holds only 100 `sample_devices`, client-side features (interactive table search, CSV export) operate solely on the 100-device sample.
   - Tab buttons lack JavaScript event handlers, causing tab switching to be non-functional.

## 3. Caveats

1. **Explicit Device Ownership Attribute**:
   - The Microsoft Graph API query in `fetch_intune_data.py` did not request the `managedDeviceOwnerType` property.
   - Consequently, ownership cannot be distinguished as `company` vs `personal` from a dedicated raw field; it is inferred from corporate UPN enrollment (`@coforge.com`, 99.60%). Future Graph API fetches should add `managedDeviceOwnerType` to `$select`.
2. **SolarWinds / Network / DEX Endpoints**:
   - The current data files in `data/` only contain Intune telemetry. SolarWinds, Network CMDB, and DEX sections are designated as P0 in the MRD but currently display "Awaiting VM" or lack backend data feeds.
3. **Full Client-side Dataset Load Performance**:
   - Loading the full 25,987 devices (approx. 7.5 MB raw JSON) directly into browser memory for client-side search/table rendering could incur a small initial parse overhead (~150ms). Pagination or streaming CSV generation is recommended for optimal user experience.
